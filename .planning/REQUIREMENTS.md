# REQUIREMENTS.md — v1.0 发票邮件筛选 Skill

> 来源：PRD v1.0（2026-07-28）。本文档为 v1.0 里程碑的**完整范围**（FR-1 ~ FR-10 全部纳入）。
> 每条需求标注：所属阶段（→ Phase N）与验收标准（UAT）。

## FR-1 邮箱连接（IMAP） → Phase 2

- 服务器 `imap.qiye.aliyun.com`，端口 993（SSL）；
- 凭证：账号 + 登录密码（首选）；强制客户端授权码时切换账号 + 授权码（备用，`auth_type: password|authcode`）；
- 凭证存 `config.yaml`，热更新（下次定时任务自动生效）；
- 安全：config.yaml 不入 Git；日志不打印密码/授权码明文。

**UAT-1**：正确凭证连接成功并列出未读邮件数；凭证错误时弹确认栏「邮箱登录失败，请检查 config.yaml 中的凭证」，本次运行安全终止，不修改任何邮件状态。

## FR-2 未读邮件拉取与防重 → Phase 2

- 每次运行拉取收件箱全部**未读**邮件；
- 处理前对照输出目录 `processed_emails.json`（已处理邮件 Message-ID），已处理直接跳过；
- 单封**处理成功后**按固定顺序执行：① IMAP 标记已读 → ② Message-ID 写入 processed_emails.json；
- 中途失败的邮件**保持未读**，下次运行自动重试。

**UAT-2**：同一封邮件不进入两份报告；人为中断后重跑，未完成邮件能被重新处理。

## FR-3 开票邮件识别 → Phase 3

命中任一即判定开票邮件：

| 规则 | 位置 | 关键词 |
|---|---|---|
| R1 | 邮件正文文本 | 「发票」或「开票」 |
| R2 | 正文表格标题 | 「发票申请」 |

三分类：开票邮件（进 FR-4）/ 其他邮件（不处理不提醒）/ 疑似不确定邮件（均不命中但无法明确判定无关，如正文过短、只有附件无正文、格式异常 → 进报告疑似区）。

**UAT-3**：历史样本中正常开票邮件 100% 识别；纯通知/广告邮件不进报告；拿不准的出现在疑似区。

## FR-4 表格解析与字段提取 → Phase 3

模版：标准《开票申请汇总表》15 列（第 1 行大标题，第 2 行表头，第 3 行起数据行，预留空行跳过）。仅提取 3 字段：

| 模版列 | 字段 | 说明 |
|---|---|---|
| 第 8 列 | 开票金额（实付订单金额） | 原样提取，如 `1880元`、`3904` |
| 第 10 列 | 订单号 | 可能带前缀（如 `主订单ID：…`），供 FR-6 清洗 |
| 第 14 列 | 备注 | 原样提取 |

**多行聚合**：同一邮件多行 = 同一订单 → 合并为一条订单记录；金额保留所有行明细（列表）；备注取首个非空值。

**UAT-4**：徐亚素 / edna / 模版(1) 三份样例提取结果与人工一致；多行邮件正确聚合且金额明细完整。

## FR-5 加急识别 → Phase 3

- 位置：邮件正文文本；关键词：`加急`；命中 → 订单标记「加急」，否则「常规」。

**UAT-5**：含「加急」样例（ZZF 同学发票申请）正确标记。

## FR-6 订单号校验 → Phase 4

1. 清洗：提取全部连续数字（去 `主订单ID：`、空格、换行等）；
2. 校验：纯数字长度 12 或 16 位 → 正常，否则异常。

分类去向：加急+正常 → 加急表；加急+异常 → 加急表且异常表；常规+正常 → 正常表；常规+异常 → 异常表。

**UAT-6**：`9000000782190489`（16 位）→ 正常；`主订单ID：9000000784169034\n` → 清洗后正常；10 位 / 13 位 / 空值 → 异常。

## FR-7 跨邮件订单号去重 → Phase 4

| 场景 | 保留规则 |
|---|---|
| 重复中至少一条加急 | 留加急；多条加急留**后出现**的 |
| 重复均非加急 | 留**后出现**的 |
| 不重复 | 全保留 |

- 去重维度：本次运行全部邮件 + `processed_emails.json` 历史订单号（`dedup.check_history`，默认开启）；
- 被丢弃订单不进任何表格，不单独汇报。

**UAT-7**：两封同订单号邮件（一常规一加急），报告只保留加急条。

## FR-8 报告生成 → Phase 5

输出目录：`E:\File\XQDWorkFile\财务开发票\开发票-开发\test_发票邮件拦截校验报告`
命名：`{YYYY.M.D}_{HH-mm}_发票邮件报告.{md|xlsx}`（Windows 文件名禁冒号，时间用 `HH-mm`）。

### .md（给大模型）

- 头部：运行时间、处理未读邮件数、开票邮件数、加急/正常/异常/疑似数量；
- 区块顺序：**加急订单（最前，订单号加粗）** → 正常订单 → 订单号异常 → 疑似不确定邮件；
- 订单表列：`订单号 | 开票金额 | 备注 | 来源邮件主题 | 发件人 | 邮件时间`；
- 异常表列：`订单号原文 | 清洗后数字 | 异常原因 | 开票金额 | 备注 | 来源邮件主题 | 发件人 | 邮件时间`；
- 疑似表列：`邮件主题 | 发件人 | 邮件时间 | 不确定原因`。

### .xlsx（给人类，5 Sheet）

| Sheet | 内容 |
|---|---|
| 1 汇总 | 运行时间、各分类数量 |
| 2 加急订单 | 同 .md 订单列；订单号加粗、整行标黄 |
| 3 正常订单 | 同 Sheet2 结构 |
| 4 订单号异常 | 同 .md 异常表列 |
| 5 疑似不确定邮件 | 同 .md 疑似表列 |

**UAT-8**：双文件生成到指定目录、命名合规；.md 为纯文本标准 Markdown 表格可被下游直接解析；.xlsx 5 Sheet 结构正确且加急 Sheet 视觉突出。

## FR-9 定时任务 → Phase 6

- 默认每小时一次；`config.yaml` 的 `schedule.interval` 可配（`30m`/`1h`/`2h`/`1d` 简写），修改后下次调度生效；
- 实现：**脚本内调度器**（常驻 Python 进程，已决策）。

**UAT-9**：每小时自动运行；改配置后周期生效。

## FR-10 异常处理 → Phase 6（贯穿 Phase 2-5）

| 场景 | 处理 |
|---|---|
| 登录失败（凭证错/网络断） | 弹确认栏，本次运行终止，不动邮件状态 |
| 单封解析失败 | 保持未读，进报告疑似区（原因「解析失败」），其余继续 |
| 凭证临近失效 | 每次运行先探活，失效提示「登录已过期，请更新 config.yaml 凭证」 |
| 输出目录不存在 | 自动创建 |

- 测试配合：开发方提供 mock 邮件样本 / 模拟 IMAP 数据做解析失败边界测试。

**UAT-10**：解析失败邮件进疑似区且保持未读；输出目录自动创建。
