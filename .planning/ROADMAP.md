## Phase 1 — 项目骨架与配置系统

**目标**：搭好可运行、可配置、可测试的工程地基。

**范围**：
- 目录结构（`src/` 模块化拆分、`tests/`、`samples/` mock 邮件样本）；
- `config.yaml` 加载器 + 热更新（每次运行重读）+ 缺省值兜底；
- 日志模块（脱敏：不打印密码/授权码）；
- tkinter 弹窗工具（确认栏提示，供 FR-1/FR-10 复用）；
- `processed_emails.json` 读写工具（Message-ID + 历史订单号索引）；
- `.gitignore`（config.yaml、输出报告、processed_emails.json、`__pycache__`）；
- mock 邮件样本构造（覆盖 PRD 附录 B 4 类样例 + 无关/疑似邮件）。

**完成标准**：`python -m src.main --dry-run` 能加载配置并打印脱敏后的配置摘要；mock 样本可被测试引用。

## Phase 2 — IMAP 连接与未读邮件拉取

**目标**：稳定连上邮箱，拉到未读邮件，双重防重机制落地。

**范围**：
- IMAP SSL 连接（账号+密码 / 账号+授权码两种 auth_type）；
- 连接探活 + 失败弹窗 + 安全终止（不动邮件状态）；
- 未读邮件拉取（uid + Message-ID + 主题/发件人/时间/正文）；
- 对照 `processed_emails.json` 跳过已处理；
- 单封处理成功后：标记已读 → 写 json（顺序固定）；失败保持未读；
- 日志脱敏验证。

**UAT**：UAT-1（凭证对/错两路径）、UAT-2（中断重跑不丢不重）。

## Phase 3 — 邮件识别与字段提取

**目标**：三分类识别 + 表格解析 + 加急标记。

**范围**：
- R1/R2 关键词识别（关键词走 config.yaml）；
- 三分类路由（开票 / 其他不提醒 / 疑似不确定进报告）；
- HTML/纯文本正文提取；HTML 表格解析（《开票申请汇总表》15 列，跳过大标题/表头/空行）；
- 第 8/10/14 列提取；多行聚合成单订单（金额明细列表、备注取首个非空）;
- 加急识别（正文含「加急」）；
- 解析失败 → 保持未读 + 疑似区（原因「解析失败」）。

**UAT**：UAT-3、UAT-4（三份样例与人工一致）、UAT-5。

## Phase 4 — 订单号校验与跨邮件去重

**目标**：订单状态分类 + 全局去重。

**范围**：
- 订单号清洗（提取连续数字）+ 12/16 位校验（长度走 config.yaml）；
- 四象限分类（加急/常规 × 正常/异常）；
- 跨邮件去重（有加急留加急，否则留后出现；可选对齐历史订单号）；
- 去重丢弃不进任何表。

**UAT**：UAT-6（16/12 位、带前缀、10 位、13 位、空值）、UAT-7（常规+加急重复只留加急）。

## Phase 5 — 双格式报告生成

**目标**：一键产出 .md + .xlsx 双报告。

**范围**：
- 报告聚合数据结构（Phase 3/4 产出的统一输入）；
- .md 生成（加急区最前 + 订单号加粗；三类表格固定列序）；
- .xlsx 生成（5 Sheet；加急 Sheet 订单号加粗、整行标黄）；
- 文件命名 `{YYYY.M.D}_{HH-mm}_发票邮件报告`；输出目录自动创建。

**UAT**：UAT-8（命名、结构、加急视觉突出、.md 可被下游按列名解析）。

## Phase 6 — 定时调度与端到端容错

**目标**：常驻调度 + 全链路异常兜底 + 端到端联调。

**范围**：
- 脚本内调度器（读 `schedule.interval` 简写：30m/1h/2h/1d；改配置下一轮生效）；
- 每次运行前凭证探活；失效提示「登录已过期」；
- 全链路异常兜底（网络断、单封失败不阻塞批次）;
- 端到端联调：mock IMAP 数据跑完整流水线 → 双报告；
- 性能验证：100 封 < 2 分钟；
- 真实邮箱联调（依赖用户填凭证 + 提供真实样本）。

**UAT**：UAT-9、UAT-10 + 里程碑总验收（PRD §9 全 10 项）。
